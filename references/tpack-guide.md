# TPACK 教学策略标注指南

在第4层 Traceability Engine 中，每个设计决策需要标注其背后的教学策略和 TPACK 区域。
本文件提供标注的判断规则和示例。

---

## TPACK 七区域快速判断

```
T = 技术知识（工具/API/数据结构/框架能做什么）
P = 教学知识（学习策略/脚手架/形成性实践）
C = 内容知识（领域概念/课程结构/学科逻辑）

TP = 技术直接实施教学策略（"这个功能本身就是教学动作"）
PK = 教学法针对特定内容（"教这个科目用这种方式"）
CK = 领域知识嵌入系统逻辑（"系统知道在学什么"）
TPK = 三者全部交叉（甜点功能，优先级最高）
```

**判断顺序**：先问"这个决策的驱动力是T/P/C中的哪一个"，再问"它有没有同时涉及另外两个"。

## 常用教学策略词汇表

在 Traceability 节点中，`pedagogy.strategy` 字段从以下选取：

| 策略名称 | 何时使用 |
|---|---|
| 形成性评价 | 系统持续监测学习行为并实时给出反馈 |
| 脚手架 | 系统为学习者提供结构化支持，随能力提升逐步撤除 |
| 苏格拉底式提问 | 用引导性问题促进批判性思考，而非直接给答案 |
| 等待时间策略 | 给学习者足够的沉默时间思考，不立刻干预 |
| 同伴学习/协作学习 | 学习者相互教授、相互评价 |
| 公平参与 | 确保所有成员都有平等机会表达 |
| 元认知支持 | 帮助学习者觉察自己的思维过程 |
| 情境学习 | 学习发生在真实或模拟的真实情境中 |
| 渐进式揭示 | 信息逐步呈现，减少认知负荷 |
| 即时反馈 | 学习行为发生后立刻给出反馈 |
| 社会化学习 | 通过观察他人、模仿、互动来学习 |
| 自主学习支持 | 学习者自主控制学习节奏和路径 |

## TPK 甜点功能的识别标准

以下三个条件同时满足时，标注为 TPK：

1. **技术选择有教学理由**：不是因为"技术上容易做"，而是因为"这种技术实现方式符合某教学策略"
2. **教学策略是领域敏感的**：不是通用策略，而是针对这个具体内容/学科/情境调整过的
3. **内容知识影响了实现细节**：系统的某个具体行为依赖于"它知道在学什么"

**示例**：过度发言检测（发言比例>40%触发干预）
- T：比例计算算法
- P：公平参与教学策略（有名字的教学理论）
- C：针对小组讨论场景（不是所有内容学习都适合这个干预）
→ 三个都满足 → TPK ✅

**反例**：CSV导出按钮
- T：Blob生成 + 浏览器下载 ✅
- P：支持教师行动研究 ✅
- C：与具体内容无关 ❌
→ 只有TP，不是TPK
