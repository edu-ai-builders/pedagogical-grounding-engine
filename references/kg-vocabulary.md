# KG 谓词词汇表

所有三元组统一使用以下谓词，确保 Core KG 和 Context KG 的节点可以被第3层正确对齐。

---

## 结构性谓词（描述"是什么"）

| 谓词 | 含义 | 示例 |
|---|---|---|
| `由...组成` | 整体→部分 | `LLM智能体 → 由...组成 → 四个模块` |
| `包含` | 弱包含关系 | `参与度监控 → 包含 → 静默检测` |
| `是一种` | 分类 | `非活跃学生 → 是一种 → 参与度状态` |
| `定义为` | 操作性定义 | `检测周期 → 定义为 → 1分钟静默` |
| `映射至` | 对应关系 | `用户名 → 映射至 → 颜色编码` |
| `测量` | 量化关系 | `发言频率 → 测量 → 参与度水平` |

## 过程性谓词（描述"怎么运作"）

| 谓词 | 含义 | 示例 |
|---|---|---|
| `触发` | 条件→启动 | `静默>60秒 → 触发 → 对话理解` |
| `读取` | 访问输入 | `对话理解 → 读取 → 历史Map` |
| `计算` | 产生数值 | `参与度监控 → 计算 → 发言频率` |
| `分类为` | 归类操作 | `发言频率==0 → 分类为 → 非活跃` |
| `传递至` | 数据流向 | `非活跃学生 → 传递至 → 回复生成` |
| `生成` | 产出结果 | `智能体 → 生成 → 建设性反馈` |
| `检测到` | 识别事件 | `误解 → 检测到 → LLM智能体` |
| `激活` | 达到阈值后启动 | `第10轮 → 激活 → 问题卡生成` |
| `存储` | 持久化 | `历史Map → 存储 → {用户ID,内容,时间}` |

## 因果/影响谓词（描述"有什么效果"）

| 谓词 | 含义 | 示例 |
|---|---|---|
| `提升` | 正向影响 | `同伴式语气 → 提升 → 参与意愿` |
| `约束` | 负向限制 | `纯提示词LLM → 约束 → 多用户感知` |
| `支持` | 使能 | `形成性nudge → 支持 → 沉默学习者` |
| `促进` | 增加可能性 | `同伴建模 → 促进 → 社会化学习` |
| `依赖` | 前置条件 | `误解检测 → 依赖 → 领域概念图` |

## 设计性谓词（描述"如何实现"）

| 谓词 | 含义 | 示例 |
|---|---|---|
| `可视化` | 渲染为UI元素 | `参与度 → 可视化 → 彩色仪表盘` |
| `操作化` | 抽象→具体 | `公平参与 → 操作化 → 发言比例检测` |
| `实例化` | 概念→具体实现 | `苏格拉底提问 → 实例化 → 问题卡` |
| `脚手架支持` | 提供结构化帮助 | `改写辅助 → 脚手架支持 → 语言学习者` |
| `替代` | 简化替换 | `内存Map → 替代 → 数据库` |
| `导出为` | 格式转换 | `会话指标 → 导出为 → CSV` |
| `体现` | 物化某个理论 | `等待时间理论 → 体现于 → 静默检测` |

## 知识关系谓词（论文间关系）

| 谓词 | 含义 | 用途 |
|---|---|---|
| `启发` | A理论启发B设计 | 跨论文推理 |
| `补充` | A机制补充B机制 | 多篇合并 |
| `冲突` | A主张与B主张矛盾 | 冲突标注 |
| `扩展` | A是B的特化/扩展 | 层级关系 |

## 常见 EdTech 三元组集群

以下集群在论文中高频出现，优先识别：

### 参与度检测集群
```
静默阈值 → 定义为 → N秒
静默 → 触发 → 参与度检查
参与度检查 → 分类为 → {主动/被动/非活跃}
非活跃 → 触发 → 智能体响应
智能体响应 → 设置为 → {nudge/问题/摘要}
```

### 脚手架写作集群
```
草稿 → 输入至 → 智能体分析
智能体 → 识别 → 写作弱点
写作弱点 → 触发 → 定向反馈
定向反馈 → 脚手架支持 → 修订过程
```

### 形成性评价集群
```
学习事件 → 检测到 → 系统
系统 → 生成 → 即时反馈
即时反馈 → 目标指向 → 特定学习者
反馈语气 → 设置为 → {同伴式/教师式/中性}
```

### 公平参与集群
```
发言次数 → 计算 → 人均比例
比例 > 阈值 → 分类为 → 主导发言者
主导发言者 → 触发 → 重新平衡提示
```

## Representation Translation 词汇（阶段4b 专用）

### implementation_form 词汇表

在 enriched triple 的 `implementation_form` 字段中，必须从以下选择：

| 词汇 | 含义 | 适用场景 |
|---|---|---|
| `graph_schema` | 定义图的节点类型、边类型和属性结构 | 构念关系、知识结构、图谱设计 |
| `ui_feature` | 对应一个具体的界面功能 | 用户可交互的功能模块 |
| `prompt_rule` | 编码为系统提示词中的一条规则 | 行为约束、角色定义 |
| `workflow_step` | 对应工作流中的一个步骤 | 过程性知识、操作序列 |
| `constraint` | 作为设计约束（Must/Tradeoff/Nice）| 边界条件、不可违反的原则 |
| `metric` | 作为可测量的成功指标 | 学习效果、参与度、质量指标 |
| `information_structure` | 决定信息的呈现方式 | 图/序列/层级/对比/网络 |

### mechanism 词汇表（认知机制）

`mechanism` 字段必须命名一个具体的认知/学习机制：

- 检索练习（Retrieval Practice）
- 间隔重复（Spaced Repetition）
- 元认知监控（Metacognitive Monitoring）
- 认知冲突（Cognitive Conflict）
- 精细化询问（Elaborative Interrogation）
- 自我解释（Self-Explanation）
- 同伴学习（Peer Learning）
- 脚手架逐步撤除（Scaffolding Fading）
- 负迁移预防（Negative Transfer Prevention）
- 工作记忆卸载（Working Memory Offloading）
