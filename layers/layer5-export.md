# 第5层：产物导出 + Commands 系统

## 层定位

> **目标**：从 Traceability Engine 的决策节点集合中，按需导出不同格式的产物。
> **核心设计**：命令式（Command-driven），流水线跑完后用户用 /命令 按需召唤，无需重跑。
> **幂等性保证**：相同命令在相同流水线结果上，总是产出相同的输出。

---

## 输入契约（Preconditions）

| 输入项 | 要求 |
|---|---|
| 第4层汇总 Canvas JSON | 已生成，meta 字段完整 |
| 所有 Traceability 节点（层A + 层B）| P0/P1 都有完整 JSON |
| Constraint Layer | 约束节点和关系已命名 |

---

## 流水线完成时的标准输出

流水线（第1-4层）完成后，**必须立即输出以下内容**，然后等待命令：

```
✅ 流水线完成
   论文：[论文列表]
   场景：[场景摘要一句话]
   决策节点：P0×N / P1×M / P2×K
   约束关系：冲突×A / 权衡×B / 强化×C

━━━━━━━━━━━━━━━━━━━━━━━━━━
可用命令：

/trace      Traceability Map（汇总表 + Canvas JSON）
/render     直接渲染可交互 Canvas 图（React Flow）
/kg         KG 原始图数据（Core + Context + Constraint）
/prompt     System Prompt（含所有来源标注）
/prd        PRD + TASKS + DESIGN 三份规格文件
/workflow   Workflow 步骤序列
/constraint Constraint Layer 详细报告
/why [名称] 解释某功能"为什么是这个设计而不是别的"
/diff [A] [B]  两篇论文的构念冲突与融合分析
/export     导出所有产物

输入命令开始 →
━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 命令规范

---

### /trace

**产出**：Traceability Map 完整版

**A1. Markdown 汇总表**：

```markdown
| 决策名称 | 优先级 | 约束冲突 | Resolution（牺牲了什么）| Core KG来源 | 教学策略 | TPACK | 影响决策 |
|---|---|---|---|---|---|---|---|
| [名称] | P0 | [约束A] vs [约束B] | [取舍方案]（牺牲[X]）| [论文简称] | [策略] | TPK | [decision_XXX] |
```

**A2. 汇总 Canvas JSON**：直接输出第4层阶段4生成的完整 JSON。

**输出规范**：
- Markdown 表格先输出，JSON 在表格之后
- JSON 用 ` ```json ` 包裹
- 表格行数 = 决策总数

---

### /render

**产出**：可在 Claude artifact 中直接预览的 React Flow 组件

**生成规范**：
1. 读取汇总 Canvas JSON 的 nodes 和 edges
2. 生成完整自包含的 `.jsx` 文件（不依赖外部数据文件）
3. 节点着色使用 Canvas JSON 的 `color_legend`
4. 边样式：dashed 对应虚线，solid 对应实线
5. 节点点击行为：

```tsx
// 点击 decision 节点 → 右侧面板展开该节点的推理链（层A内容）
// 点击 constraint 节点 → 展开 claim + resolution 摘要
// 点击 artifact 节点 → 展开产物描述
// 点击 resolution 节点 → 展开 sacrifice + alternative_considered
```

6. 布局：使用 Canvas JSON 的 x_hint/y_hint 作为初始位置，允许用户拖拽
7. 包含图例（右上角小面板）：TPACK 着色说明 + 边类型说明

**输出规范**：
- 生成完整 `.jsx` 文件，不是代码片段
- 文件开头注释：`// Generated by Pedagogical Grounding Engine`
- 可以直接复制到任何 React 环境运行

```json
  }

```

### /prompt

**产出**：完整 System Prompt，含所有来源标注

**生成规范**：
1. 只使用 `artifact.type === "prompt_segment"` 的决策节点
2. 每条规则后附来源标注：`[来源: decision_XXX | Resolution: [一句话]]`
3. 按教学法逻辑排列，不是按决策优先级排列
4. 包含：角色定义、核心行为规则、触发条件与响应、边界条件

**输出格式**：
````markdown
```
## 系统提示词

### 角色定义
[来源: decision_XXX]

### 核心行为规则
1. [规则内容] [来源: decision_XXX | Resolution: ...]
2. ...

### 触发条件与响应
- 当 [条件] → [响应] [来源: decision_XXX]

### 边界条件
- 不做：[行为] [来源: 约束 constraint_XXX]
```
````

---

### /prd

**产出**：PRD.md + TASKS.md + DESIGN.md 三份文件

**生成规范**：
- 只使用 `artifact.type === "ui_feature"` 的决策节点
- PRD 每个功能附：Traceability 节点ID + constraint_resolution 一句话摘要
- TASKS 按第4层决策优先级排序：P0 先做，P1 次之，P2 最后
- DESIGN 数据结构来自第4层决策节点的具体内容描述

**技术栈硬性约束**（每次都要重申，不允许例外）：
- Next.js 14 + TypeScript + Tailwind + shadcn/ui + lucide-react
- 存储：`Map<string, T[]>` 内存存储，禁止任何数据库
- LLM：OpenAI API 直接 fetch，最多3个不同的 `/api/llm/[route]`
- 禁止：身份认证、WebSocket/Socket.io、测试文件、里程碑标记

详细模板见 `references/spec-templates.md`。

---

### /workflow

**产出**：Workflow 步骤序列

**生成规范**：
- 只使用 `artifact.type === "workflow_step"` 的决策节点
- 每步包含：触发条件、执行动作、预期输出、来源标注
- 按执行顺序排列（参考跨决策依赖关系）

```markdown
## Workflow：[场景名称]

### 步骤 N：[步骤名称]
- **触发条件**：[何时触发]
- **执行动作**：[做什么]
- **预期输出**：[产生什么]
- **来源**：[decision_XXX | 教学策略: ...]
```

---

### /constraint

**产出**：Constraint Layer 完整报告

包含：
1. 所有约束节点（JSON + 可读描述）
2. 所有约束间关系（含 Resolution + alternative_considered）
3. **Constraint Layer 摘要**（第3层的叙事段落）
4. **设计空间分析**：如果某个 pedagogical 约束被移除，哪些设计决策会改变？

---

### /why [功能名称]

**产出**：针对单个功能的完整设计辩护

**生成规范**：
1. 找到对应的 decision_XXX 节点
2. 输出完整推理链（层A内容）
3. 展开 `alternative_considered`：被排除的方案是什么，为什么排除
4. **反事实分析**：如果某个约束改变，这个决策会如何变化（列出3种反事实场景）

**反事实分析格式**：
```
如果约束 [X] 改变为 [Y]：
→ [具体描述设计决策会如何变化]
→ 新的牺牲点：[...]
```

---

### /diff [论文A] [论文B]

**产出**：两篇论文的比较分析

包含：
1. 构念冲突清单（Core KG 中的 `[冲突]` 节点）
2. 互补关系（合力强化了哪些设计方向）
3. 覆盖盲区（A有B没有，反之亦然）
4. **在当前场景下的优势对比**：哪篇论文的机制在这个场景更直接有用？

---

### /export

**产出**：所有命令的输出打包

执行顺序：/trace → /constraint → /prompt → /prd → /workflow → /kg

每个命令输出之间用分隔线隔开：
```
━━━━━━━━━━━━━━━━━━━━━━━━
[命令名称] 输出
━━━━━━━━━━━━━━━━━━━━━━━━
[内容]
```

## 错误处理

| 错误情况 | 处理 |
|---|---|
| 用户调用 /prd 但没有任何 `ui_feature` 决策 | 说明"当前决策节点中没有 UI 功能类型，建议用 /prompt 或 /workflow" |
| 用户调用 /why 时功能名称不匹配 | 列出所有可用功能名称，让用户选择 |
| /render 时 Canvas JSON 节点超过50个 | 警告"节点数量较多，渲染可能复杂"，提供分组渲染选项（按 P0/P1/P2 分批）|
| 用户在流水线未完成时调用命令 | 说明流水线未完成，询问是否继续完成流水线 |
